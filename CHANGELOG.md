# История изменений

## 0.2.0 — 2026-08-11

- Демонстрационный двухэтапный сценарий заменён четырьмя этапами из `Ситуации для игры_final.xmind`.
- Красные команды получили ветку «Якорь», а синие — связанную ветку «Шахта / Вышка / Птица».
- Последующие ситуации и подписи решений учитывают ранее подтверждённые найм, подряд, скидку, PR-мероприятие и аванс бонуса.
- Три одновременных решения синей команды в Q2 сохраняются как один составной аудируемый выбор из восьми комбинаций.
- Панель организатора показывает фактическое число этапов вместо фиксированного значения прототипа.
- Добавлены unit-тесты полноты сценария и ключевых межэтапных последствий.

## 0.1.0 — 2026-08-10

- Перед запуском каждого этапа организатор может вручную задать его длительность от 1 до 1440 минут.
- Выполненные действия в карточках команд подсвечиваются светло-зелёным, а дублирующая нумерация `01`, `02` удалена.
- Панель организатора получила компактные карточки, отдельные колонки красных и синих команд и игровую иллюстрацию в шапке.
- Исправлен тихий пропуск Telegram-рассылки: отсутствие токена у подключённой команды теперь фиксируется как ошибка доставки, а в панели доступна повторная отправка этапа.
- Создан первый рабочий прототип панели семи команд.
- Добавлен двухэтапный сценарий, подтверждение решения и загрузка Excel.
- Реализованы глобальный таймер, принудительный выбор организатора и Telegram webhook-контур.
- Добавлены demo-режим, базовая аутентификация и unit-тесты.
- Создан Supabase PostgreSQL-проект и добавлена начальная схема игровых данных.
- Добавлена безопасная health-проверка подключения к базе.
- Игровой API переведён на транзакционное хранение состояния в Supabase PostgreSQL.
- Сохранены постоянные привязки капитанов, решения, файлы, журнал событий, статусы доставки и идемпотентность Telegram webhook.
- Добавлен живой интеграционный тест PostgreSQL с проверкой восстановления состояния из нового экземпляра репозитория и конкурентной дедупликации updates.
- Добавлены интеграционные проверки HTTP API: запуск игры, чтение панели, валидация админ-команд и защита Telegram webhook.
- Production запускается только с `DATABASE_URL` и не откатывается незаметно на временную память.
- Добавлен GitHub Actions quality gate с `pnpm check` и `pnpm build`.
- Репозиторий подключён к Vercel, а обязательные server-side переменные добавлены в Preview и Production environments.
- CI и Vercel унифицированы на Node.js 24, совместимом с pnpm 11.16.
- Vercel deployment проверен на реальном URL: интерфейс, вход организатора и соединение с Supabase работают.
