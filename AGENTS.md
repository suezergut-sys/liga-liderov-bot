# Правила работы с репозиторием

## Область действия

Правила действуют для всего репозитория.

## Архитектура

- Приложение обслуживает семь Telegram-ботов одним игровым движком и одной админ-панелью.
- Сценарии хранятся отдельно от переходов и интеграционного кода.
- Любой подтверждённый или принудительный выбор должен оставлять аудируемую запись.
- Telegram webhook-обработчики обязаны быть идемпотентными по паре `botKey + update_id`.
- Секреты, Telegram-токены и реальные персональные данные не добавляются в Git.

## Работа с изменениями

- Перед правкой изучить README, package scripts и соседний код.
- Сохранять несвязанные пользовательские изменения.
- Реализовывать минимальный целостный change.
- Для подтверждённого дефекта добавлять регрессионный тест.
- Не редактировать generated-файлы вручную.

## Документация

При изменении функций, API, данных, переменных окружения, команд или deploy обновлять README и CHANGELOG в том же PR.

## Проверки

Перед публикацией выполнить:

```bash
pnpm check
pnpm build
```

Для рискованных API, auth, файловых и Telegram-сценариев добавить integration-тест или ручную проверку.

## GitHub и production

- Публиковать работу из отдельной ветки через pull request без force push.
- После успешных обязательных проверок самостоятельно выполнять merge готового pull request в `main`, если пользователь явно не запретил merge для конкретной задачи.
- Не выполнять merge draft pull request, pull request с конфликтами, упавшими обязательными проверками или незакрытым `changes requested`.
- После merge дождаться Vercel deployment `Ready` и проверить production URL.

## Критерий готовности

Код, тесты и документация согласованы; проверки успешны; обязательные GitHub/Vercel-шаги подтверждены; реальные ограничения перечислены явно.
